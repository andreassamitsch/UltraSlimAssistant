# Public Samsung source archive analysis

The public release archives are supplied by the owner via a temporary pCloud share. Use repository secret `PCLOUD_SOURCE_LINK` (full European share URL or code). Do not use a workflow input, commit the link, print the URL, or share download tokens. After setting the secret, manually run **Samsung open-source analysis** on main. Pushes run a synthetic self-test only. The workflow has read-only repository access, checks the share metadata and name, downloads up to 2 GiB and calculates SHA256, then recursively scans ZIP and TAR family archives. It never executes archive contents, writes member names as paths, or retains the source archive as an artifact. Temporary data is cleaned on exit. Logs are public: selected source snippets only from the expected publicly released Samsung archive; no pCloud code or signed URL.

The first-pass scan inventories archive hierarchy and searches for HyperUART, MediaTek platform, documented debugging interfaces, service/package management, audio capture, microphone/DSP, and security model. Counts/paths/line evidence support follow-up file-specific review. A match is not proof of device functionality; absence is not proof of absence. Limits and unrecognized formats are reported. This is a research pipeline, not a firmware installer. No device change.

The assistant's GitHub connection does not support creating repository secrets or dispatching a workflow. Owner must add the secret and initiate the manual run. Once the first pass completes, inspect evidence and target further reading before claiming an implementation path.
